## 3.1 问题：一个类型装不下所有情况

考虑一个简单需求：一个值，可能是一个整数，可能是两个整数之和，也可能是一个整数取负。

### 3.1.1 Python（等其他语言）实现

Python 中最直接的表示是元组加标签：

```python
("lit", 3)
("add", 1, 2)
```

元组的第一个位置是**标签**（tag），说明这是哪一种情况；其余位置是**载荷**（payload），即这种情况附带的数据：`("add", 1, 2)` 的载荷是 `1` 与 `2`，`("lit", 3)` 的载荷是 `3`。二者都是普通元组元素，类型系统不检查它们的个数与类型是否与标签相符，`("add", 1)` 缺少第二个操作数、`("lit", 1, 2)` 多了一个，都能构造出来，错误要到运行时才暴露。改用类层次可以避免其中一部分。

把元组换成类层次，是 Python 项目的常见做法：三个节点各写一个类，`eval` 声明为抽象方法，
各子类实现。

```python
{{#include ../code/python/eval_classes.py:classes}}
```

`@dataclass` 自动生成 `__init__`，字段声明即构造参数，因此构造子的参数个数被固定下来。运行：

```
$ python3 code/python/eval_classes.py
-4
TypeError: Lit.__init__() takes 2 positional arguments but 3 were given
```

第二行是 `Lit(1, 2)` 的结果。类层次解决了元组版的一半问题：参数个数写错会立即失败。但错误
仍发生在运行时，只是从"求值到该节点时"提前到"构造该节点时"；在长驻进程里，这条路径可能几
小时后才被执行。

🦂 另一半没有解决：`Expr` 是一个开放的集合。`data` 声明在一处列出全部构造子，别处无法追加；类层次正相反——`Expr` 只是基类，任何模块都能新增子类，没有任何地方登记"共有哪些节点"。因此"某个操作是否覆盖了全部节点"缺少检查的前提：它需要一份完整名单，而名单不存在，且随时可能变长。

后果分三种：新子类忘了实现 `eval`，实例化时抛 `TypeError`（抽象基类兜底），但没人实例化就不报；实现了 `eval` 却没实现 `pretty`，要等到调用 `pretty` 才发现；某处若仍用 `isinstance` 分支列表，漏掉的分支永不报错。

开放本身不是缺陷。它使增加节点只需新增一个类，不必改动已有代码；代价是完整性从"可检查"变成
"靠约定"。

### 3.1.2 Haskell 实现

Haskell 的做法是把"有哪几种情况、每种情况带什么"写进类型本身：

```haskell
data Expr
    = Lit Int
    | Add Expr Expr
    | Neg Expr
```

这一声明确立了三件事：`Expr` 是一个类型；`Lit`、`Add`、`Neg` 是三个构造子，各自接受指定
数目的参数；一个 `Expr` 值只能是三者之一。构造之后只能按这三种方式使用，没有第四种可能。

三者对照：

| 方面 | 元组加标签 | 类层次 | `data` |
|---|---|---|---|
| 有哪些情况 | 开放 | 开放 | 封闭，声明处唯一 |
| 参数个数 | 不检查 | 构造时检查（运行时） | 编译时 |
| 一个操作写在哪 | 一处，靠 `isinstance` 分支 | 分散在各节点类中 | 一处，靠模式匹配 |

增加节点与增加操作的代价，即 1.2.4 节的表达问题，此处不再重复。本章关心的是第一行：
`data` 把"有哪几种情况"变成可以在编译时检查的对象。这是 3.2 节的和类型与 3.4 节的消去规则得以成立的前提。

## 3.2 积、和、单位与空

`data` 的语义可以用三种基本构造说明。

**定义 3.1（积）** 给定类型 $A$ 与 $B$，它们的积 $A \times B$ 是一个类型，配两个投影
$\pi_1 \colon A \times B \to A$、$\pi_2 \colon A \times B \to B$。其定义性质是：对任意类型
$C$ 与一对函数 $f \colon C \to A$、$g \colon C \to B$，存在唯一的 $h \colon C \to A \times B$
使 $\pi_1 \circ h = f$ 且 $\pi_2 \circ h = g$。

```haskell
{{#include ../code/src/Ch03/ADT.hs:pair}}
```

积的用法由两个投影确定：给定 $A \times B$，可以得到 $A$，也可以得到 $B$。上述唯一性刻画的就是"除了分别取出两个分量，积不携带别的内容"，它在范畴论中称为积的泛性质（第 7 章）。数学上，$|A \times B| = |A| \cdot |B|$。

**定义 3.2（和）** 给定类型 $A$ 与 $B$，它们的和 $A + B$ 是一个类型，配两个注入
$\iota_1 \colon A \to A + B$、$\iota_2 \colon B \to A + B$。对任意类型 $C$ 与一对函数
$f \colon A \to C$、$g \colon B \to C$，存在唯一的 $h \colon A + B \to C$ 使
$h \circ \iota_1 = f$ 且 $h \circ \iota_2 = g$。

```haskell
{{#include ../code/src/Ch03/ADT.hs:sum-product}}
```

**例 3.1（把 `Shape` 写成和与积）** `Shape` 的每个构造子各自是一个积：`Circle` 持有一个
`Double`，`Rect` 持有两个。整个类型是这些积的和。和类型的用法由分情况确定：给定一个  `Shape` 与两个处理函数，总能得到一个结果。这就是 `area` 的写法：按构造子分两支，各支只处理自己持有的字段。数学上 $|A + B| = |A| + |B|$。

**单位与空**：只有一种取值的类型（`()`）对应 $1$；没有取值的类型（`Void`，`Data.Void`）对应 $0$。二者是上述两种构造的退化情形。

**定义 3.3（代数数据类型）** 由 $0$、$1$、积、和经有限次组合得到的类型，称为代数数据类型。

任何 `data` 声明都等价于这样的组合。`Shape` 即
$\mathrm{Double} + (\mathrm{Double} \times \mathrm{Double})$，"代数"一词由此而来：类型的元素个数可以按算术计算。

**例 3.2（按算术计算元素个数）** 两个类型的元素个数按算术相加、相乘：

```haskell
data Tri = A | B | C          -- 3 = 1 + 1 + 1
data PairTri = PairTri Tri Tri -- 9 = 3 × 3
```

这一算术不是类比。若把类型理解为集合，$+$ 与 $\times$ 就是集合的不交并（disjoint union）与 Cartesian 积，其基数满足上述等式。

## 3.3 `data` 声明

### 3.3.1 构造子与模式匹配

一个 `data` 声明由类型名、构造子名与字段类型组成：

```haskell
data Shape
    = Circle Double
    | Rect Double Double
    deriving (Eq, Show)
```

读法是：`Shape` 类型的值，要么由 `Circle` 与一个 `Double` 构成，要么由 `Rect` 与两个
`Double` 构成。`Circle` 与 `Rect` 不是类型，是构造子；它们的作用是把字段打包成 `Shape`。

🦂 用 3.1 节的词说：构造子即标签，字段即载荷。`Circle` 的载荷是一个 `Double`，`Rect` 的载荷
是两个 `Double`。注意源码中并不出现单独存放标签的位置：标签由构造子本身承担。运行时要区分
构造子，由编译器在堆对象的头部记录；这一步在源码层面看不到，不能据此认为运行时没有标签。

模式匹配是相应的消去方式：

```haskell
area (Circle r) = pi * r * r
area (Rect w h) = w * h
```

左侧的 `(Circle r)` 既是匹配，也是绑定：若传入的值由 `Circle` 构造，则把其字段绑定到 `r`。
一个 `data` 声明通常配一组方程，每个构造子一条。

### 3.3.2 递归类型

**例 3.3（自然数）** 构造子的字段可以引用正在定义的类型：

```haskell
{{#include ../code/src/Ch03/ADT.hs:nat}}
```

`Nat` 有两个构造子，`Succ` 的字段是 `Nat` 本身。这使类型可以表示任意有限大的自然数，与
`Integer` 的区别在于结构显式可见：`Succ (Succ Zero)` 的形状就是它的定义。

**定义 3.4（递归类型）** 若一个类型的某个构造子的字段类型中出现该类型自身，则称它为递归类型。
列表、树、语法树都是递归类型。

`Nat` 满足方程 $\mathrm{Nat} \cong 1 + \mathrm{Nat}$，读作"零，或一个自然数的后继"。列表
满足 $\mathrm{List}\ a \cong 1 + (a \times \mathrm{List}\ a)$。一般地，`data` 声明的每一种
形式都对应一个这样的方程，这正是 3.2 节的算术。方程在这里不是巧合：右边是构造子的和，每个
构造子贡献一个积，递归出现的位置就是等号左边的类型。

这组类型还有一个性质，本章后面会用到：它们的相等是平凡的。两个 `Nat` 要么相等，要么不等，
不存在"以两种方式相等"。这一点的准确表述需要 HoTT，见 3.7 节。

## 3.4 消去规则

**定义 3.5（消去规则）** 给定类型 $T$ 与它的构造子 $c_1, \dots, c_n$，$T$ 的消去规则是这样

归约为对应的结果。

## 3.5 模式匹配的细节

🦂 **顺序决定语义。** 多个方程自上而下尝试，第一个匹配成功的生效：

```haskell
classify :: Shape -> String
classify (Circle _) = "round"
classify _          = "other"     -- 若与上一行交换，所有值都会落到这里
```

交换两行不改变能否编译，但会改变结果，并使后一行成为**冗余分支**：`-Wall` 报
`Pattern match is redundant`（实测）。这一点与函数定义的等式性质有关：方程不构成"集合"，而是
一个有序的匹配序列。若把方程当作集合来读，就会误以为顺序无关。

**穷尽性**。若某个构造子没有对应方程，`-Wall`（1.2.2 节）会给出警告。以下是本机实际输出：

```
Pattern match(es) are non-exhaustive
In an equation for 'area':
    Patterns of type 'Shape' not matched: Rect _ _
```

警告而非错误，意味着程序仍可编译，缺失分支在运行到该输入时才会失败。这类警告不应忽略。

**冗余分支**。若某个方程被前面的方程完全覆盖，编译器同样会警告。冗余分支通常意味着前面的
模式写得过宽，或者需求已经变化而代码未同步。

**记录语法**。字段较多时可以为字段命名：

```haskell
data Rect = Rect { width :: Double, height :: Double }
```

此时 `width`、`height` 同时成为选择函数（`Rect -> Double`），并且可以按字段名构造与更新。
命名便于阅读，代价是自动生成的选择函数可能与已有名字冲突。

**`newtype` 与 `data`**。两者都能定义新类型，区别在运行时表示：`newtype` 只有一个构造子且
只有一个字段，编译后与该字段同表示，没有额外开销；`data` 则可能有多个构造子，需要标签来区分。
因此 `newtype` 适用于"给已有类型加一层类型级别的标记"，不适用于需要分支的情形。

## 3.6 常见错误

**构造子名与类型名混淆。** `data Shape = Circle Double | ...` 中，`Shape` 是类型，`Circle`
是值层的函数 `Double -> Shape`。写 `Circle :: Shape` 会得到类型错误，因为 `Circle` 还需要
一个参数。

**忘记 `deriving`。** `Eq`、`Show` 等实例不会自动生成。未派生 `Show` 的类型在 GHCi 中无法
直接打印，报错信息会指向缺少实例，而不是数据定义本身。

**记录字段重名。** 两个记录类型使用同名字段时，选择函数会冲突。较新的 GHC 允许 `DuplicateRecordFields`，
但更简单的做法是给字段加前缀，或使用 `data` 加显式投影函数。

**把 `newtype` 用在该用 `data` 的地方。** `newtype` 只有一个字段，无法表达"两种形状之一"；
反之，`data` 包一个字段会多一层间接，在性能敏感的代码中不必要。

## 3.7 HoTT：类型作为空间

前面各节把类型当作集合，元素个数可以数，相等是一个判断。这一节换一种解释：类型是空间，
相等是路径。换解释的收益是，它同时说明了哪些性质由语言保证，哪些性质语言无法表达。

### 3.7.1 基本对应

**HoTT 的四条基本对应**（HoTT Book 第 1–2 章）：

- 类型 $A$ 解释为空间，$A$ 的项解释为该空间的点；
- 函数 $f \colon A \to B$ 解释为**连续映射**：它把 $a$ 到 $b$ 的路径映射到 $f(a)$ 到 $f(b)$ 的路径；
- 给定 $a, b : A$，**恒等类型** $\mathrm{Id}_A(a, b)$ 解释为从 $a$ 到 $b$ 的路径空间；
- 常路径 $\mathrm{refl}_a : \mathrm{Id}_A(a, a)$ 是最基本的路径。

「连续」不是额外的拓扑条件，而是"保持路径"。这一点不需要假设：若 $p : a = b$，则 $f$ 作用后得到 $f(a) = f(b)$（这一构造记作 $\mathsf{ap}_f(p)$），因此任何函数都不会把路径扯断。用"连续"这个词，是因为在把类型实现为空间（单纯集合或立方集合）的模型里，函数恰好对应连续映射。

这四条是模型给出的对应，不是定义。本章只用它的三个推论：相等是路径；在集合层上相等退化为
判断；单值性取消同构与相等的界限。这三条不依赖具体选哪个模型。

### 3.7.2 路径与同伦

复合与取逆给出相等的传递性与对称性。HoTT 多出一层：两条路径相等本身又是一个类型，可以有多个
元素。集合论中没有对应物。

这一层结构正是同伦论研究的对象：路径是点之间的连续变形，两条路径之间的路径是变形的变形。
所谓"同伦"，指的就是存在一条这样的路径。因此"类型是空间"不是随口打的比方，而是一个可以
精确化的事实：在单纯集合的模型里，每个类型实现为一个 Kan 复形，路径是它的边，高阶路径是它
的高维面。

🦂 用范畴论的话说，这里有两层结构，不能混。外层：类型是对象，函数是态射，类型与函数构成一个
范畴，更准确地说是一个 $(\infty,1)$-范畴——$f$ 与 $g$ 之间的 2-态射是 $f$ 到 $g$ 的同伦。内层：每个类型 $A$ 自身是一个 $\infty$-群胚，它的态射是 $A$ 中两点之间的路径。函数 $f \colon A \to B$同时属于两层：它是外层的态射，也是内层群胚之间的映射，后者正是"连续"的确切含义。第 5 章讨论的 Hask 只用外层；在 Hask 里内层是退化的，因为本书的类型都是集合，两点之间至多一条路径。

### 3.7.3 集合与命题

**定义 3.6（集合）** 若一个类型的所有恒等类型都至多有一个元素，则称它为集合，或称 0-截断
类型。

在集合上，"$a$ 与 $b$ 相等"是一个判断，不存在"用不同方式相等"这回事。日常数学处理的几乎
都是集合。3.3.2 节末尾说"这些类型的相等是平凡的"，指的就是它们是集合。

若 $A$ 与 $B$ 是集合，则 $A \times B$、$A + B$、$A \to B$ 也是集合：前两个直接验证相等的
唯一性，函数类型还需要函数外延性。因此由 $0$、$1$、积、和构造出的代数数据类型都是集合。

**命题即类型**（propositions as types）。一个类型可以读作一个命题：类型有元素，即命题成立；
元素就是证明。若进一步要求类型的元素至多一个（-1-截断），它就退化为传统意义上的命题，因为
"怎么证明的"不再重要。

### 3.7.4 单值性

**定义 3.7（单值性）** 若 $A$ 与 $B$ 之间存在等价（双向且互逆的映射），则 $A$ 与 $B$ 之间的恒等类型本身就是该等价的空间。

用一句话说：等价即相等。集合论中"同构的对象未必相等"，例如 $\{1\}$ 与 $\{2\}$ 不同但同构；HoTT 中这条界限被取消。单值性不是本章其余论述的前提，列出它是因为它是 HoTT 与集合论最显著的差别，并且 3.7.5 节要说明 Haskell 无法表达它。

### 3.7.5 用 HoTT 读 Haskell 的类型系统

把 Haskell 的类型对应到 HoTT 的空间，有几处不成立，需要明确。

🦂 `Eq` 不是恒等类型。Haskell 的 `(==) :: Eq a => a -> a -> Bool` 是一个判定过程：它返回布尔值，说明两个值是否相等。HoTT 的恒等类型 $\mathrm{Id}_A(a,b)$ 是"相等的证明"构成的空间，本身是一个类型。二者在有穷类型上可以对应（相等可判定时，恒等类型要么为空，要么可缩为一个点），但在一般情形下不是同一件事：

- 函数类型无法给出 `Eq (a -> b)`，而 HoTT 中两个函数之间的相等（借助函数外延性）总是可以讨论的；
- 恒等类型的元素可以参与进一步构造（例如把两条路径复合成第三条），`Bool` 做不到这一点。

这一差别解释了一个常见困惑：为什么 Haskell 里"两个函数相等"无法用 `==` 判断。原因不是
实现偷懒，而是函数相等在类型论中本来就不是一个可判定的判断。

**例 3.6（模 3 相等）** 在整数上定义关系 $x \sim y$ 当且仅当 $3 \mid x - y$。这是等价关系，
可以取商。Haskell 做不到：它只能引入包装类型 `newtype Mod3 = Mod3 Int`，在构造与解构时手动
归一化，并保证所有函数都尊重这一不变式。HoTT 与立方型类型论提供**商类型**（quotient type），
取商是一步操作，Haskell 没有。

**定义 3.8（高阶归纳类型）** 除点构造子外还允许路径构造子的归纳类型，称为高阶归纳类型
（higher inductive type，HIT）。点构造子产生元素，路径构造子产生元素之间的等式。

**例 3.7（圆周 $S^1$）** 这里的圆周不是平面上的点集
$\{(x, y) : x^2 + y^2 = 1\}$，而是类型论中的对象，英文为 the circle，记作 $S^1$。它由两个构造子给出：一个点 `base`，以及一条从 `base` 到 `base` 的路径 `loop`。

`loop` 不能取为 `refl`：若取 `loop = refl`，这个类型退化为一个点，与圆周不同。`loop` 的存在
使类型 `base = base` 有许多元素（`loop`、`loop` 与其自身复合、`loop` 的逆，等等），因此
$S^1$ 不是集合。这正是它无法由一个 `data` 声明写出的原因。

$S^1$ 与平面上的单位圆同伦等价，但两者不是同一个对象：单位圆是点集，有不可数多个点；$S^1$
只有一个点构造子，其余信息都在路径里。

**没有高阶归纳类型。** `data` 只引入点，因此所有类型都是集合。圆周、区间、截断等构造无法直接声明。

**没有单值性。** Haskell 无法在类型层面表达"等价即相等"。`Coercible` 与 `newtype` 提供了运行时的零开销转换，但那是编译器的转换规则，不是类型论中的恒等。

🦂 **总性与"类型都有值"是两件事。** HoTT 的形式系统满足**强规范化**（strong normalization）：每个良类型的项，任何改写序列都在有限步内停止，得到范式。编程语言里把这一性质叫作**总的**（total）：求值必然终止，不存在 `undefined`，也不存在发散的定义——递归只能由消去规则给出，不能任意自调用。但总性不意味着每个类型都有元素：空类型 $0$ 就没有元素，它的作用正是表示"假"。总性说的是求值会停下来，不是说什么都能构造出来。

Haskell 在这两点上都不同。它允许一般递归与 `undefined :: a`，求值可能不终止；于是任何类型
都可以填进一个不终止的项，"类型有元素"这句话不再携带信息。因此"类型即空间"的对应只在忽略
$\bot$ 的意义下成立。第 6 章专门处理这一问题。

归结起来：Haskell 的类型系统落在 HoTT 的一个子集里——集合层的、无商类型、无高阶构造的类型论，
外加一个不纯粹的 $\bot$。用这一图景读代码的好处是，它同时说明了哪些性质是语言保证的，哪些是
语言无法表达的。
