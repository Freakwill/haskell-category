# 第 6 章 Hask：把类型系统当范畴看

> 状态：试写稿 ｜ 目标 1.4 万字 ｜ 代码：`code/src/Ch06/Hask.hs`

第 5 章给出了范畴的定义与几个例子。Haskell 的类型与函数看起来正好构成一个范畴，习惯上记作
**Hask**。本章先把这个范畴写出来，核对它的公理在什么范围内成立，再说明它为什么不严格满足公理，以及这对"用范畴论推理 Haskell 程序"意味着什么。

## 6.1 Hask 的定义

### 6.1.1 对象：类型

对象取 kind 为 `*` 的类型：`Int`、`Bool`、`[Int]`、`Int -> Bool`、`Maybe Char`。函数类型也
是对象，因为它本身是一个类型。

🦂 类型构造子不是 Hask 的对象。`Maybe` 的 kind 是 `* -> *`，接受一个类型才得到类型；`Maybe`
本身不在 Hask 的对象之列，它是对象上的映射。第 7 章据此定义函子：函子由"对象上的映射"与
"态射上的映射"两部分组成，`Maybe` 提供前者。

不要把这句读成"函子不是对象"。函子是相对某个范畴说的：它把 Hask 的对象映射到 Hask 的对象，
是 Hask 上的结构。若把范畴、函子、自然变换放在一起看，得到的是范畴的范畴 Cat——其中范畴是
对象，函子是态射，自然变换是 2-态射；而在函子范畴 $[C, D]$ 里，函子又是对象。层次不同，
说"函子是对象"与"函子是态射"都对，指的不是同一个范畴。

还有一处与集合范畴不同：Haskell 的类型不构成集合。`Int`、`[Int]`、`[[Int]]`……没有上界，
"全体类型"的汇集是一个开放的类。集合范畴 Set 在这一点上类似，但原因不同：**Set 的每个对象
都是集合，只是全体对象的汇集不是集合，而是真类**——若那个汇集是集合，幂集与罗素构造就能造出
矛盾。Hask 的对象则是类型，单个类型本身就不是集合。

两处都不能说"对象集"，但含义有别：Set 是汇集太大，Hask 是元素不对。若要严格地谈"Hask 的
对象集"，得先固定一个**宇宙**，本书不做这件事。

### 6.1.2 态射：函数

对对象 $A$、$B$，态射集取 `A -> B`。写作 $f \colon A \to B$，与数学记号一致。

两个特殊性在此埋下。第一，`A -> B` 本身是一个类型，也就是 Hask 的对象之一。这一层 Set 也
有：Set 的 hom 是集合，集合又是 Set 的对象。差别在下一层——Hask 的那个对象不是集合，所以
"hom-set"这个名字在 Hask 里只是沿用的习惯，实际取到的是一个类型；6.3.3 节说明它的相等不可
判定。第二，`A -> B` 的元素不都是"处处有定义"的函数，它还包含 $\bot$。第二点是 6.3 节的主题。

### 6.1.3 复合与恒等

**定义 6.1（Hask）** 以 kind 为 `*` 的类型为对象，以 `A -> B` 为态射集，以 `(.)` 为复合、
`id` 为恒等，所得结构记为 **Hask**。

```haskell
(.)  :: (b -> c) -> (a -> b) -> (a -> c)
id   :: a -> a
```

第 5 章的三条公理翻译过来是：

```haskell
f . (g . h) = (f . g) . h     -- 结合律
id . f      = f               -- 左单位
f . id      = f               -- 右单位
```

这三行是 Haskell 里最常见的等式，改写时常直接用。问题在于它们**是不是**等式。

### 6.1.4 与 Set 的对照

把 Hask 与第 5 章用过的集合范畴并排放：

| 维度 | Set | Hask |
|---|---|---|
| 对象 | 集合 | 类型（kind 为 `*`） |
| 各对象是否成集 | 是 | 否 |
| 全体对象是否成集 | 否，是真类 | 否，是开放的类 |
| 态射 | 处处有定义的函数 | `A -> B` 的元素，含 $\bot$ |
| hom 是否成集 | 是 | 否，相等不可判定 |
| 公理 | 成立 | 只在无 $\bot$ 的部分成立 |

表只列差别，不下结论。第三行的结论见 6.1.1 节，第四到第六行的结论在 6.3 节。前五行并起来
是一个对照：Set 的每一格都能在 ZFC 里说清，对象、态射、hom 都是集合，全体对象虽不是集合
（是真类），仍是 ZFC 公式可定义的类；Hask 的对应格子只能写成类型论的语言：类型、含 $\bot$ 的
`A -> B`、不可判定的相等。

## 6.2 定律在哪里成立

对处处有定义的函数，三条定律成立。结合律只用复合的定义；单位律还差一步 η-展开，见 6.2.2。

### 6.2.1 结合律的等式证明

结合律：对任意 $x$，

$$
\big((f \circ g) \circ h\big)(x) = (f \circ g)(h\,x) = f\,(g\,(h\,x)),
\qquad
\big(f \circ (g \circ h)\big)(x) = f\,\big((g \circ h)(x)\big) = f\,(g\,(h\,x)).
$$

两边化简到同一个式子，因此相等。每一步都只用了复合的定义，没有用到 $f, g, h$ 的任何性质。

**例 6.1（在具体函数上核对三条定律）** 取 `f = (+ 1)`、`g = (* 2)`、`h = subtract 3`，
在一组输入上逐条核对：

```haskell
{{#include ../code/src/Ch06/Hask.hs:laws}}
```

测试中的断言为：

```haskell
lawsHoldOn (+ 1) (* 2) (subtract 3) [0, 1, 5, -2]  -- True
```

### 6.2.2 η-展开

单位律的证明要多一步。

**定义 6.2（η-等式）** 对函数 $f$，

$$
f = \lambda x.\, f\,x \tag{η}
$$

它说的是"函数由它在每一点上的取值决定"，即外延性的函数版本。有了它，两条单位律各一行：

$$
id \circ f = \lambda x.\, id\,(f\,x) = \lambda x.\, f\,x = f,
\qquad
f \circ id = \lambda x.\, f\,(id\,x) = \lambda x.\, f\,x = f.
$$

中间一步用 $id$ 的定义，最后一步用 η。右边对 $f$ 没有任何要求，看上去处处成立。

在数学里 η 是恒等式，在 Haskell 里不是。左边与中间是 λ，最右边的 $f$ 可能是 $\bot$。这层
差别在 6.3.2 节变成反例。

## 6.3 三处不成立

### 6.3.1 每个类型都有 ⊥

**定义 6.3（⊥）** Haskell 的每个类型都含一个不终止的计算，记作 $\bot$。`undefined`、
`error "..."`、死循环都是它的具体形式。

于是 `A -> B` 的元素比"从 $A$ 到 $B$ 的函数"多。多出来的部分包括：处处不定义的函数、在某些
输入上不终止的函数、返回 `error` 的函数。范畴论的 hom-set 里没有这些东西。

**定义 6.4（弱头范式与 `seq`）** 一个值若最外层是构造子或 λ，称它处于**弱头范式**（weak
head normal form，WHNF）。`seq a b` 先把 $a$ 求值到 WHNF，再返回 $b$；若求值 $a$ 时抛出
异常或不终止，`seq` 也不返回。

这个定义解释了 6.3.2 的机制：函数的"值"是 λ，求值到 WHNF 只需造出闭包，不进入函数体。

**例 6.2（`Void -> a`）** 若只计全函数，$0 \to a$ 恰有一个元素：空函数。它不需要指定任何
映射，因为源类型没有元素；"没有输入"不减少函数的个数，反而把唯一的全函数确定下来。在
Haskell 里这个类型不止这一个元素：

```haskell
{{#include ../code/src/Ch06/Hask.hs:void}}
```

`absurdFromBottom` 通过类型检查，它的值是 $\bot$。标准库给出的是另一个东西：

```haskell
absurd :: Void -> a
```

它是那个全函数，但永远不会被调用，因为 `Void` 没有值可供传入。两个版本的区别在于：前者是
"有了一个不存在的东西"，后者是"从不存在推出任何东西"——后者才是逻辑上正确的那一个。只计
全函数时，数学上恰好一个；Haskell 里是那一个，加上无穷多个 $\bot$。

### 6.3.2 单位律在 ⊥ 上失效

🦂 失效的是单位律，不是结合律。结合律两侧都化简为同一个 λ：

```haskell
(f . g) . h  →  \x -> f (g (h x))
f . (g . h)  →  \x -> f (g (h x))
```

两行是同一个表达式，即使 $f$、$g$、$h$ 中有 $\bot$ 也一样——复合的定义先造出 λ，不碰里面的
东西。所以结合律在 Hask 里成立。

单位律不同。它依赖 η-展开：`id . f` 的定义是 `\x -> id (f x)`，与 `f` 只差一层 λ。对普通的
函数，这层 λ 无关紧要；对 $\bot$，它决定求值是否立即失败。

**例 6.3（`seq` 区分 `id . f` 与 `f`）** 取 `f = undefined :: Int -> Int`，分别在 `seq`
下求值：

```haskell
{{#include ../code/src/Ch06/Hask.hs:eta}}
```

运行的真实输出：

```
$ runghc -isrc ch6demo.hs
(True,False)
```

第一个 `True`：`id . undefined` 是一个 λ，求值到 WHNF 立即成功，`seq` 看到的是"有值"。
第二个 `False`：`undefined` 本身求值即失败，抛出 `Prelude.undefined`。

同一段代码换成集合论的眼光无法解释：两边都应当是"处处不定义的函数"，同一个东西。差别来自
Haskell 的求值模型：函数的定义在求值到 WHNF（定义 6.4）时只造闭包，不进入函数体；`seq` 恰好
停在这个层面。数学上的相等不区分"造出闭包"与"进入函数体"，而`seq` 区分。

结论：`id . f = f` 在 Haskell 里只对处处有定义的函数成立。Hask 满足范畴公理的范围，是全函数
那一部分。

### 6.3.3 态射的相等不可判定

范畴论要求 hom 是集合：两个态射要么相等，要么不等。Hask 的 hom 是类型 `A -> B`，而在
Haskell 里判断两个函数是否相等是不可判定的——这已在 3.7.5 节以 `Eq (a -> b)` 的缺失出现过。
真实报错：

```
eqf.hs:2:34: error: [GHC-39999]
    • No instance for 'Eq (Int -> Int)' arising from a use of '=='
      (maybe you haven't applied a function to enough arguments?)
```

这条信息里的括号是对初学者的提示：`==` 需要两个同类型的参数，若只给一个，GHC 会猜你想比较
函数。真正的理由是 `Eq (a -> b)` 这个实例不存在，而它不存在是因为函数相等不可判定。

🦂 所以严格说，Hask 的 hom 不是集合，而是一个类型。要把它变成集合，必须人为规定"外延相等"
的商，而那个商无法计算。第 5 章定义 5.1 里"对每一对对象，一个态射的汇集"这句话，在 Hask 里
只能读作"一个类型"，不能读作"一个集合"。

三类困难叠在一起：对象不成集、hom 含 $\bot$、hom 的相等不可判定。Hask 因此是一个**近似
范畴**：结构与定律对得上，公理只在限制下成立。

## 6.4 三条出路

### 6.4.1 只谈全函数

最常见的做法是明确规定：忽略 $\bot$，把态射理解为处处有定义的函数。这样 Hask 满足公理，
等式推理可以照常使用。

这套做法有名字：**fast and loose reasoning**——先在只含全函数的理想语言里推理，再把结论搬回
Haskell。搬得回去有精确的条件：Danielsson 等人构造了一个关系（**偏等价关系，PER**），它的定义域
是"处处有定义"的项，两个函数只在参数相关时才相关。**定理** 两个闭合项在理想语言里语义相同，
则在 Haskell 里这一对语义相关。因此结论只在全函数这一层成立——一旦某项可能是 $\bot$，它就落
在关系之外。

判断标准因此有两条：

- 用到的等式是否只涉及数据构造与模式匹配？若是，安全。
- 是否涉及 `seq`、严格性注解、异常，或"求值顺序会影响结果"的情形？若涉及，前一步的结论
  全部作废。

**例 6.4（安全与不安全的分界）** `map f . map g = map (f . g)` 对任意 $f, g$ 成立，包括
$f$ 或 $g$ 为 $\bot$ 的情形：两边都在遍历到该元素时失败。这是安全的一侧。`foldl' (+) 0` 与
`foldr (+) 0` 的替换则不安全：两者在全函数上结果相同，在内存占用与短路行为上不同，而那点
差别来自求值时机，正是 $\bot$ 所在的那一层。

### 6.4.2 换到 CPO

若要把 $\bot$ 纳入语义，就得换对象。标准做法是**domain theory**：对象取带 $\bot$ 的完全
偏序（pointed CPO），态射取连续函数。

**定义 6.5（连续函数）** 设 $D$、$E$ 是带 $\bot$ 的偏序集，且每条递增链都有上确界。
$f \colon D \to E$ 称为连续的，若 $f$ 单调，且对每条递增链 $(x_n)$ 有
$f\left(\bigsqcup_n x_n\right) = \bigsqcup_n f(x_n)$。

连续性保证"逼近的极限被保留"，这正是 $\bot$ 与递归定义需要的性质。$f$ 可以是 $\bot$，因为
偏序里有最小元；`seq` 在这个范畴里有合法位置，不必排除。

**例 6.5（平坦域）** 取自然数集加一个最小元：$D = \mathbb{N}_\bot$，序关系为 $\bot \le n$
对一切 $n$ 成立，其余元素互不可比。这称为**平坦域**。这里的序是**信息序**：$\bot \le n$ 指
$n$ 比 $\bot$ 确定得更多；两个不同整数互不可比，指信息上谁也不包含谁，与 `==` 的比较无关。
$D$ 的元素正是 Haskell 中 `Int` 的语义值：每个整数，或者 $\bot$。

🦂 当定义域与值域都是平坦域时，单调函数只有两种：严格函数（$f(\bot) = \bot$），以及常函数
（$f$ 处处取同一个值）。理由是一旦 $f(\bot) = n$，单调性要求 $n \le f(x)$ 对一切 $x$ 成立，
而平坦域里除了 $n$ 本身没有元素大于 $n$。这与程序员的直觉相反：多数"正常"函数都是严格的，
而它们能存在，是因为 `Int -> Bool` 这类类型的语义不是平坦域，而是函数域——序关系逐点定义，
$\bot$ 与具体值之间有更多中间状态。

代价是：每个对象都要有近似结构，每个态射都要证明连续，而 Haskell 的类型系统不表达这些。换到
CPO 得到的是 Haskell 的**语义模型**，不是 Haskell 的类型系统本身。本书只用它说明"为什么
不成立"，不进入细节。

### 6.4.3 把定律当义务

第三条路是 4.5 节的延续：承认定律是义务，不是数据。`Functor` 的实例应当满足
`fmap id = id` 与 `fmap (f . g) = fmap f . fmap g`，编译器不检查，文档里写着，测试里抽查。

这条路的实践含义最清楚：**用范畴论做设计，用 $\bot$ 与 `seq` 做优化，两者不要混在同一段
推理里**。设计时假设公理成立，能推出该有的结构；优化时承认求值时机可观测，不要指望等式推理
还管用。混着用的典型后果是：证明了一个等式，再靠改写求值顺序"优化"，最后结果不同，却说不
出哪里错。

## 6.5 常见错误

**以为 `Functor` 定律由编译器检查。** 它不检查。写一个违反 `fmap id = id` 的实例，
`cabal build` 一样通过，只有 code review 与测试能发现。

**以为 `undefined` 只是一个错误值。** 它是每个类型的元素，占着 hom-set 的一个位置，并且
破坏 η-等式。以为它"只会出现在调试代码里"，就解释不了 6.3.2 的反例。

**把 `Maybe` 当成 Hask 的对象。** `Maybe` 的 kind 是 `* -> *`，不是 `*`。要把它变成对象，
得先应用一个类型参数，例如 `Maybe Int`。

**以为 Hask 是 Set 的子范畴。** "实例"不是范畴论术语，这个误解说全了是：Hask 的对象是
Set 的对象、态射是 Set 的态射，即 Hask 是 Set 的子范畴。子范畴要求两者都属于 Set：对象得
是集合，类型不是（6.1.1 节）；态射得是集合论函数，`A -> B` 含 $\bot$；再把 hom 商成集合
也不行，因为相等不可判定。三条都不满足。

**用 `seq` 优化之后，继续用等式推理。** `seq` 能观测到的差别，正好是等式推理看不见的差别。
引入 `seq` 就要重新核对哪些等式仍成立。

## 6.6 练习

1. 写出 `Maybe` 的 kind，并给出两个把 `Maybe` 变成 Hask 对象的表达式。
2. 证明：即使 $f$、$g$、$h$ 中有 $\bot$，`(f . g) . h` 与 `f . (g . h)` 仍化简为同一个 λ。
   说明这为什么使结合律免于 6.3.2 的反例。
3. 用 `seq` 构造另一个反例：找出两个在集合论意义下相等的函数，使 `seq` 能区分它们。
   （提示：从 `\x -> x` 与 `\x -> id x` 出发，把其中一个换成 $\bot$。）
4. 证明：对任意处处有定义的 $f \colon A \to B$，`id . f = f`。指出证明中哪一步在 $f = \bot$
   时不成立。
5. 证明 `map f . map g = map (f . g)` 对含 $\bot$ 的 $f, g$ 仍成立。（提示：对列表结构归纳，
   空列表与 `x : xs` 分别处理；$f$ 为 $\bot$ 时两边同时失败。）
6. 说明在 CPO 里 $f = \bot$ 为什么是合法的态射，而在 Hask 里它破坏公理。
